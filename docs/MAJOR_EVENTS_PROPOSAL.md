# 新主要事件提案（草案，供作者審閱）

> 狀態：**提案，尚未實作**。本文只新增此檔案，未更動任何事件資料或程式。
> 目標：新增 **20 個**非兩岸題材的「主要事件」（`tier: "major"`）與 3 個 `chainOnly` 後續事件，補足「主要事件一局只出現一次」之後的空缺，讓三十年不再太安靜、結局不再集中在「現狀的三十年」。

---

## 為什麼需要

引擎現在把主要事件改為**一局只出現一次**（`Engine.oncePerGame`），而非系統、非彩蛋的主要事件模板只有 **28 個**（`rate` 合計約 12.4）。每年 2.4 次的抽籤三十年共約 72 次，幾乎會把模板抽完：實測一局平均只看見約 **27 個**主要事件，後半局抽籤常常落空，世界變得平靜，結局因此容易落在門檻最寬的「現狀的三十年」。

本提案刻意**不從台灣自身歷史取材**，而是把其他國家真實發生過的事件與可信的未來情境「通用化」後搬到台灣：不點名真實政治人物與政黨、不抄襲真實災難的傷亡數字、不做某一場外國悲劇的影射重述。

## 設計原則

1. **格式完全沿用 `EventDef`**：`tier: "major"`，不需要 `once`（引擎已保證一局一次）；id 以分類前綴加 `_m_`（`eco_m_`／`pub_m_`／`dis_m_`／`int_m_`／`pol_m_`），已比對現有 263 個 id 無碰撞。
2. **幅度比照既有主要事件**：原始 `effects` ±3…9（引擎 ×1.5）、`local` ±2…15、`policy` 位移 ±2…6、期間 1095–3650 天。每個選項都有真實取捨，沒有「嚴格最佳解」：便宜的選項會留下後遺症或後續事件，貴的選項用 `over`／`policy` 把回報延後。
3. **2–4 個選項，天意看局勢**：每個事件都用 `mods` 讓不干預的結果反映當下（信任低→混亂選項更可能、經濟好→砸錢選項更可能），用 `cond` 決定何時合理（第 N 年後、科技或經濟達門檻、人口已經很低……）。
4. **嚴格中立**：20 個事件中 **19 個完全不碰** `govLean`／`popLean`／`tension`／`dep`，戲劇性全部放在經濟、社會、治理、環境與國際地位。唯一碰到 `tension`／`dep` 的「新貿易集團成形」以**等幅鏡像選項**處理；「投票年齡公投」只用 `govToPop`（對兩端對稱）。`mods` 一律不用 `govLean`／`popLean`／`absGov`／`absPop`。
5. **事件鏈只留三條**：晶圓廠「火速復工」→「復工後二度事故」、火山「暫不疏散」→「小規模噴發」、高鐵「舉債／民間興建」→「工程預算暴增」。後續事件皆為 `general` + `chainOnly`，不佔主要事件池。
6. **文字上限**：標題 ≤ 14 字、描述 40–90 字（可用 `{county}`）、選項 ≤ 14 字、結果 ≤ 30 字；本文件由腳本逐一檢核。

## 預期影響與要盯的平衡桿

- **每局主要事件數**：模板從 28 個增為 48 個，`rate` 合計從 12.4 增為 19.6。抽籤次數不變（2.4 次／年 × 30 年 ≈ 72 次），但後半局不再落空：粗略蒙地卡羅（狀態條件以每局成立比例近似、`elapsed` 依抽籤時間把關）估計一局平均從約 22 個升到約 40 個；這個估計對現況偏保守（實測約 27 個），按比例換算實作後約為 **40–45 個**，仍低於 72 次抽籤，因此主要事件的節奏不會比原設計更密，只是不再提前用完。
- **結局多樣性**：新事件把壓力放在 `stability`、`gdp`、`trust`、`demo`、`tech`、`intl`，而不是 `govLean`。「繁榮之島」（安穩 70／財富 65／經濟 65）與「矽之盾」（科技 90／國際 80）的門檻在長期政策堆疊後更可能達到；「風雨飄搖」（安穩 < 35）與「沉睡之島」（人口 < 20 且經濟 < 45）在連續吃到核災、擠兌、人口緊急狀態後也更可能出現。「現狀的三十年」仍是預設，但不再是唯一常見的結果。
- **要盯的桿**（建議實作後跑 `npm run simulate` 比對）：
  1. `tools/simulate.ts` 的偏統／偏獨機器人分差仍須在 2 分以內（只有「新貿易集團成形」會動到 tension／dep，若分差擴大先看它）。
  2. **崩解與枯竭結局**：新事件的 `stability` 負向較多（核災、火山、擠兌最重，單次國家值 −6…−7 再 ×1.5），請看 `collapse`（安穩 ≤ 8 連續 60 天）與 `bankrupt` 的比例是否明顯上升；若上升，先把 `local` 的 −15 降到 −12，而非動 `effects`。
  3. **trust 政策堆疊**：主權基金、個資外洩、停擺、核災、人口緊急狀態都有 `trust −2…−3` 的長期政策，最壞情況同時生效約 −12 × 0.75 = −9 的平衡點位移；若信任長期偏低，把其中兩三個改成 `over` 即可。
  4. **demo 政策**：人口緊急狀態的 `demo +6（10 年）` 與青年失業、投票年齡的小幅 demo 政策可能疊加；請看「沉睡之島」是否變得太少。
  5. **intl 漂移**：多個事件的「國際合作」選項都給 `intl +3…+5`，加上既有事件，請看「矽之盾」結局是否過於頻繁；必要時把 `int_m_games_bid` 的 `cond` 提高到 `intl ≥ 50`。
  6. **`rate` 整體縮放**：若希望新舊事件各佔一半抽籤，新事件 `rate` 整體 ×1.7；若希望新事件偏稀有，×0.7。單一事件的相對稀有度不必動。
  7. **守護指數**：`guardianScore` 以 stability／wealth／gdp 等為主，新事件的負面選項單次最多約 −8 分，與既有「百年大震」「全球金融風暴」同量級。
